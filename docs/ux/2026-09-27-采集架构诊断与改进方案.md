## 二、根因分析

### 2.1 正文污染（26.4%）— 最严重

**根因**：`collectors/base.py` 第 381-382 行

```python
if not content and soup is not None:
    content = self._clean(soup.get_text(" ", strip=True))
```

当 `trafilatura.extract()` 返回空（JS 渲染页、表格密集页、非标准 HTML），降级到 `soup.get_text()`，该方法**不做任何正文识别**，直接抓取全页文本，包括：

- 导航栏文字（"首页 / 政务公开 / 互动交流"）
- 页脚信息（"联系我们 / 网站地图 / 友情链接"）
- 侧边栏推荐（"相关链接 / 热门点击"）
- 版权声明、ICP 备案号

**实测**：trafilatura 2.2.0 实际可用，但对政府网站的非标准 HTML 提取率约 70%，剩余 30% 降级到 `get_text()` 产生污染。

### 2.2 采集效率低

| 瓶颈 | 现状 | 影响 |
|------|------|------|
| 速率限制 | 3 秒/请求/源 | 145 源 × 3s = 7.25 分钟（仅列表页） |
| 并发度 | 单线程串行 | 无并行采集 |
| 详情页 | 每条记录额外 1 次请求 | 1762 条 × 1s = 29 分钟 |
| robots.txt | 每源首次检查 | 额外延迟 |
| 全量耗时 | 估算 40-60 分钟 | 一轮完整采集近 1 小时 |

### 2.3 反爬封锁（37 源）

- `playwright_executable_path` 指向 ms-playwright 构建路径，但**未安装**
- `playwright_fallback` 配置为 True 但实际降级为静态请求
- cloudscraper/curl-cffi 对部分 WAF（如知道创宇、阿里云 SLB）无效

### 2.4 无质量门禁

采集后直接入库，没有：
- 正文质量评分
- 污染特征检测
- 自动重试/换策略
- 人工标注反馈环

## 三、开源 AI 搜索引擎可行性评估

### 3.1 方案对比

| 方案 | 类型 | 适合本场景？ | 理由 |
|------|------|-------------|------|
| **SearXNG** | 元搜索引擎 | ❌ 不适合 | 聚合搜索结果，不做深度站内采集。适合"发现新源"，不适合"从已知145个政府站抓全量公告" |
| **Crawl4AI**（已装） | AI 爬虫 | ✅ 适合 | 已在项目中，支持 JS 渲染 + 内容剪枝 + Markdown 输出，但仅用于列表页，未用于详情页正文抽取 |
| **Firecrawl** | 开源爬虫 | ⚠️ 可选 | URL→Markdown，质量好，但需自部署，对政府站反爬无特殊处理 |
| **Jina Reader API** | 在线 API | ⚠️ 备选 | 免费 URL→Markdown，质量高，但依赖外部服务、有速率限制、政府站可能被墙 |
| **MindSearch** | AI 搜索代理 | ❌ 过重 | Agent 式深度搜索，面向问答场景，不适合批量结构化采集 |
| **goose3** | 文章抽取 | ✅ 补充 | 专为新闻/文章正文抽取，可作为 trafilatura 的第二降级 |
| **newspaper3k** | 新闻抽取 | ✅ 补充 | 同上，对新闻类公告效果好 |
| **readability-lxml** | 正文抽取 | ✅ 补充 | Mozilla Readability 移植，通用性强 |

### 3.2 核心判断

> **本项目的本质不是"搜索引擎"，是"结构化数据采集"。**
>
> 145 个源是**已知**的政府公告列表页，不需要"搜索"去发现它们。问题在于：
> 1. 从这些页面**干净地抽取正文**
> 2. **足够快**地完成全量采集
> 3. **绕过反爬**拿到 JS 渲染内容
>
> 开源 AI 搜索引擎解决的是"从海量网页中找到相关信息"，而本项目需要的是"从指定页面提取干净内容"。两者问题域不同。

### 3.3 可借鉴的能力

虽然不需要完整的 AI 搜索引擎，但可以借鉴其**组件能力**：

| 借鉴能力 | 来源 | 用途 |
|---------|------|------|
| 内容剪枝（Pruning） | Crawl4AI | 替代 trafilatura，基于文本密度剪除导航/页脚 |
| Markdown 输出 | Crawl4AI / Firecrawl | 结构化输出，天然去除 HTML 框架 |
| 批量异步爬取 | Crawl4AI | 并发采集，提升效率 |
| JS 渲染 | Playwright / Crawl4AI | 处理 JS 动态加载的公告列表 |
| 正文质量评分 | 自研 | 采集后门禁，拒绝污染内容 |

## 四、改进方案（按优先级）

### P0：修复正文污染（立即，影响 26.4% 数据）

**方案 A：多级抽取链**

```
trafilatura.extract()
    ↓ 空/短
goose3.extract()          # 新增，新闻/文章抽取
    ↓ 空/短
readability-lxml.html2text()  # 新增，Mozilla Readability
    ↓ 空/短
Crawl4AI PruningContentFilter  # 已有，基于文本密度剪枝
    ↓ 空/短
soup.get_text()  # 最后降级，但加污染检测
```

**方案 B：污染检测门禁**（与 A 同时上）

```python
POLLUTION_PATTERNS = [
    "联系我们", "网站地图", "友情链接", "导航",
    "ICP备", "版权所有", "技术支持",
    "首页", "政务公开", "互动交流",  # 政府站通用导航
]

def is_polluted(content: str) -> bool:
    """检测正文是否被站点框架文字污染"""
    if len(content) < 100:
        return True
    pollution_hits = sum(1 for p in POLLUTION_PATTERNS if p in content)
    # 命中 5 个以上污染特征，或污染特征占比 > 3%
    if pollution_hits >= 5:
        return True
    pollution_chars = sum(content.count(p) for p in POLLUTION_PATTERNS)
    if pollution_chars / len(content) > 0.03:
        return True
    return False
```

采集后检测，若污染则：
1. 标记 `quality_mark = "polluted"`
2. 尝试用下一级抽取器重新提取
3. 仍污染则不入库或入库但标记待人工复核

**预期效果**：污染率从 26.4% 降至 < 5%

### P3：Crawl4AI 深度集成（3-5 天，质量+效率双提升）

Crawl4AI 已安装但未充分利用。深度集成方案：

```python
# collectors/crawl4ai_detail.py
from crawl4ai import AsyncWebCrawler, CrawlerRunConfig
from crawl4ai.content_filter_strategy import PruningContentFilter
from crawl4ai.markdown_generation_strategy import DefaultMarkdownGenerator

async def extract_detail(url: str) -> dict:
    config = CrawlerRunConfig(
        markdown_generator=DefaultMarkdownGenerator(
            content_filter=PruningContentFilter(
                threshold=0.48,  # 文本密度阈值
                threshold_type="fixed",
                min_word_threshold=10,
            ),
        ),
        wait_for="css:body",
        page_timeout=30000,
        cache_mode="bypass",
    )
    async with AsyncWebCrawler() as crawler:
        result = await crawler.arun(url, config=config)
        return {
            "content": result.markdown.fit_markdown,  # 剪枝后的干净 Markdown
            "title": result.metadata.get("title", ""),
        }
```

**优势**：
- `PruningContentFilter` 基于文本密度算法，自动剪除导航/页脚/侧边栏
- `fit_markdown` 是剪枝后的干净内容，天然解决污染问题
- 内置 JS 渲染，解决动态加载
- 支持批量异步，解决效率问题

## 六、结论

### 开源 AI 搜索引擎可行吗？

**直接用作采集引擎：不可行。** 本项目是"从 145 个已知源结构化采集"，不是"从全网搜索相关信息"。SearXNG/MindSearch 等解决的是后者。

**借鉴其组件能力：可行且推荐。** Crawl4AI（已安装）的 PruningContentFilter + Markdown 输出 + 异步批量，正好解决本项目的三大痛点（污染、效率、反爬）。

### 最小可行改进（本周可做）

1. **安装 goose3 + readability-lxml**（10 分钟）
2. **实现多级抽取链 + 污染检测**（半天）
3. **回溯清洗 466 条污染记录**（半天）
4. **全量重采验证**（1 小时）

**预期效果**：污染率 26.4% → < 5%，数据可用性显著提升，项目"有数据"且"数据干净"。
