# retention-ops

## 触发

数据量增长、重复抓取、保留期限、过期清理、备份恢复、邮件去重或调度失败时使用。

## 目标

保持数据可追溯、可恢复、可清理，同时避免误删政策和高价值历史资料。

## 工作流

1. 读取 `AGENTS.md`、`config/sources.yaml` 和存储模型。
2. 统计来源覆盖、重复率、content_hash 变化、待复核记录、过期记录和通知去重记录。
3. 按 `retention_class` 计算 `retention_until`，先输出 dry-run 清单。
4. 检查 `source_sync_state` 的 next_due、失败退避和任务锁。
5. 验证 SQLite/未来数据库备份可恢复，OSS 生命周期与本地保留策略一致。
6. 输出建议删除、归档、保留和人工复核数量。

## 规则

- 没有可靠发布日期或保留期限的数据不自动删除。
- `policy`、`historical` 和 `permanent` 默认保留。
- 原始正文短期缓存到期后清理，结构化结果和证据短句按策略保留。
- 删除前检查 MatchResult、用户收藏和审计依赖。
- 任何生产删除或批量 OSS 操作必须人工批准。

## 输出

数据增长报告、重复率、待清理清单、备份状态、风险和建议，不直接执行破坏性操作。
